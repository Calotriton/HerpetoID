The rule. Pages compose components; components own their styling; tokens own every colour, radius and shadow. A page that needs a new look needs a new component, defined in assets/css/main.css and shown on this page. Nothing gets an inline style attribute and nothing hard-codes a colour — tests/test_site_design.py fails the build if it does.

Identity

A field instrument, not a consumer app: graphite surfaces, one signal-amber accent, hairline rules, and a faint graph-paper grid behind the hero. The application's own interface uses a teal palette — the site is deliberately its own thing.

Monospace is reserved for machine text: labels, metadata, counters, file names, code and measurements. Prose is always in the system sans, because a page of monospace is a page nobody reads. If you are unsure which a piece of text is, ask whether a program produced it.

Colour

Two accent tokens exist because a colour bright enough to fill a button is never dark enough to be body text on paper: --accent fills, --accent-text writes. Use --data only inside diagrams, never in the interface, so the chrome keeps a single accent while a figure can still show two series.

--accent
--accent-soft
--data
--bg
--surface
--surface-2
--line
--line-strong
--text
--text-dim
--text-faint

Both themes are first-class. Define the light value on :root, then override only what differs in both the prefers-color-scheme block and the [data-theme="dark"] block — the toggle needs the second one. Use the switch in the header to check any new component in both.

Section headers

On the landing page, sections are numbered like a spec document with data-index="01" on .section-head. Keep them sequential, and leave the attribute off inside prose pages.

Checklist for anything new

  1. Built from existing components? If not, the new component is defined in main.css and shown on this page.
  2. Colours, radii and shadows come from tokens only.
  3. Readable in light and dark — use the header toggle.
  4. Keyboard reachable, with a visible focus ring; decorative marks are aria-hidden.
  5. Works at 360px wide; wide content scrolls inside its own container.
  6. pytest tests/test_site_design.py passes.
